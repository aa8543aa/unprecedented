# 블루투스 이어폰 통화 음질 문제와 무전기 방식 전환

Nov 23, 2026 · @kin

## 요약

블루투스 이어폰 마이크를 켜면 음질이 떨어지는 건 이어폰 고장이 아니라, A2DP에서 HFP로 프로필이 바뀌기 때문입니다. 원인은 이어폰 펌웨어와 OS 블루투스 스택에 있어서, Windows 앱 레벨에서는 사실상 고칠 수 없습니다.

- 가장 확실한 해결책: 통화 마이크를 이어폰이 아닌 다른 마이크로 지정해서 이어폰을 A2DP로 유지
- 만들어 볼 수 있는 것: 키를 누를 때만 HFP로 바꾸는 무전기 방식 전환 도구 (전환 지연 0.5\~1.5초 예상)
- 규격 차원의 해결책: LE Audio (양쪽 기기 모두 지원 필요)
- 평소에 핸즈프리 서비스를 꺼 두고 통화할 때만 켜는 토글도 가능. 복구 쪽은 StereoKeeper가 이미 있고, 무전기 방식은 아직 없음

## 원인: A2DP와 HFP

마이크가 켜지는 순간 이어폰이 HFP로 바뀌고, 음악도 그 좁은 통화 링크로 같이 나갑니다.

| 프로필 | 용도 | 방향 | 코덱 | 음질 |
| --- | --- | --- | --- | --- |
| A2DP | 음악 | 단방향 (PC → 이어폰) | SBC, AAC, aptX, LDAC | 44.1/48kHz 스테레오 |
| HFP | 통화 | 양방향 (SCO/eSCO 링크) | CVSD, mSBC, LC3-SWB | 8/16/32kHz 모노 |

- 16kHz 샘플링이면 8kHz 이상 고음이 잘리고 스테레오도 모노가 됩니다.
- 코덱은 이어폰이 `AT+BAC`로 지원 목록을 보내고 PC가 `+BCS`로 고르는 협상으로 정해집니다. 양쪽 모두 지원하는 코덱만 쓸 수 있습니다.
- eSCO 링크는 열 때 위·아래 방향에 같은 크기의 시간 슬롯을 예약합니다. 말을 안 해도 업링크 대역을 다운링크로 넘길 수 없습니다.

추가로 겹치는 요인은 통화 앱의 에코 제거·노이즈 억제, 그리고 Windows 소리 설정 "통신" 탭의 다른 소리 80% 감소 기본값입니다.

## 건드릴 수 있는 범위

이어폰 펌웨어는 못 바꾸므로, PC·폰 쪽 스택을 얼마나 제어할 수 있느냐가 기준입니다.

| 환경 | HFP 코덱 제어 | 비고 |
| --- | --- | --- |
| Windows | 거의 불가 | Microsoft 스택(`BthHFEnum`, `BthHFAud`)과 칩 드라이버가 결정. 앱 API 없음. 드라이버 업데이트가 전부 |
| Linux | 가능 | BlueZ + PipeWire/WirePlumber 설정으로 mSBC, LC3-SWB 활성화. 어댑터가 transparent SCO를 지원해야 함 |
| Android | 루팅 없이 불가 | 개발자 옵션은 A2DP 코덱만 선택 가능 |
| USB 블루투스 동글 | 동글이 결정 | 자체 스택으로 Windows 스택을 우회. 이어폰도 같은 코덱(예: aptX Voice 32kHz)을 지원해야 함 |

## 검토했지만 막히는 방법

| 방법 | 결과 | 막히는 지점 |
| --- | --- | --- |
| AI 음질 복원 (내 목소리) | 가능 | PC가 받은 16kHz 음성에 대역폭 확장 적용. NVIDIA Broadcast Studio Voice, AudioSR 등 |
| AI 음질 복원 (듣는 소리) | PC에서는 불가 | 음질이 PC를 떠난 뒤 블루투스 링크에서 깎임. 이어폰 안에서 처리해야 함 |
| 고속 자동 전환 | 불가 | AVDTP `SUSPEND`/`START`와 eSCO 생성이 수백 ms. 20ms 음성 프레임 사이에 끼워 넣을 수 없음 |
| HFP 마이크 + A2DP 재생 동시 사용 | 불가 | 무선 슬롯은 여유가 있지만, 이어폰 DSP가 SCO가 열리면 A2DP를 멈춤. Windows도 두 장치를 동시에 열지 못하게 함 |
| HFP 내부에서 대역 재배분 | 불가 | eSCO는 양방향 슬롯과 코덱이 동일하게 고정 |

이 문제를 규격 차원에서 푸는 게 LE Audio입니다. 방향마다 독립된 스트림(CIS)을 잡고 비트레이트를 따로 줄 수 있습니다.

## 무전기 방식 수동 전환

키를 누르는 동안만 HFP로 바꾸는 방식은 동작합니다. 단, 누를 때마다 0.5\~1.5초 기다려야 합니다.

### 동작 구조

Windows는 이어폰의 "헤드셋(핸즈프리)" 마이크 장치를 누군가 열면 HFP로, 모두 닫히면 A2DP로 돌아갑니다.

1. 키 누름 → 내 프로그램이 이어폰 마이크 스트림을 열기
2. HFP 전환 완료를 감지하면 준비 알림음 재생
3. 받은 소리를 가상 마이크(VB-Cable 등)로 전달, 통화 앱은 가상 마이크를 입력으로 사용
4. 키 뗄 → 마이크 스트림 닫기 → A2DP 복귀

통화 앱의 push-to-talk(예: Discord)는 마이크 스트림을 열어둔 채 전송만 막기 때문에 HFP가 계속 유지됩니다. 그래서 가상 마이크를 사이에 두는 게 필수입니다.

### 전환 시 일어나는 일

블루투스 연결(ACL 링크)은 유지되고, 음성 링크만 열고 닫습니다.

1. A2DP 스트림 일시정지: AVDTP `SUSPEND`
2. 코덱 협상: `+BCS` / `AT+BCS`
3. eSCO 링크 생성: HCI `Enhanced Setup Synchronous Connection`
4. 이어폰 내부 오디오 경로 전환

복귀는 반대 순서(eSCO 해제 → AVDTP `START`)입니다.

### 예상 지연

| 구간 | 예상 시간 |
| --- | --- |
| 무선 프로토콜만 | 100\~300ms |
| 실제 (스택·드라이버·펌웨어 포함) | 0.5\~1.5초 |
| 느린 이어폰 | 2\~3초 |
| A2DP 복귀 | Windows가 수 초간 HFP를 유지하는 경우 있음 |

이어폰과 PC 칩 조합마다 차이가 커서 직접 측정해야 합니다. 마이크 스트림을 연 시점부터 첫 샘플이 들어온 시점까지의 시간을 기록하면 됩니다.

### 걸리는 부분

- 키를 누르자마자 말하면 첫 마디가 잘림 (준비 알림음으로 해결)
- 말하는 동안은 듣는 소리도 HFP 음질
- 전환 시 "헤드폰(스테레오)" 장치로 나가던 소리가 끊기거나, 앱이 재생 장치를 놓칠 수 있음
- 주로 듣고 가끔 말하는 상황(회의, 게임 관전)에 맞고, 대화가 잦은 통화에는 맞지 않음

## 핸즈프리 서비스 토글 방식

평소에는 핸즈프리를 꺼 두고, 통화할 때만 켜는 "통화 모드 스위치"입니다. 무전기 방식보다 느리지만, 앱이 마음대로 HFP로 바꾸는 것을 막을 수 있습니다.

### 핸즈프리를 끄면

- HFP 장치가 사라져서 이어폰은 항상 A2DP로만 동작합니다.
- 이어폰 마이크도 같이 사라집니다. 통화는 다른 마이크로 해야 합니다.
- 그 PC의 그 이어폰에만 적용되고, 폰 연결에는 영향이 없습니다.

### 구현 방법

| 방법 | API | 권한 |
| --- | --- | --- |
| 블루투스 서비스 토글 | `BluetoothSetServiceState()` (`bluetoothapis.h`, `Bthprops.lib`) + 핸즈프리 GUID `0000111E-0000-1000-8000-00805F9B34FB` | 관리자 |
| 장치 노드 토글 | "핸즈프리 AG 오디오" 장치를 `SetupDiChangeState()` 또는 `pnputil /disable-device` | 관리자 |
| 핸즈프리 서비스 재시작 | 활성 핸즈프리 서비스만 재시작 (StereoKeeper의 소프트 리셋 방식) | 확인 필요 |

서비스 토글은 제어판 장치 속성의 "핸즈프리 텔레포니" 체크박스를 코드로 누르는 것과 같습니다.

### 장단점

- 장점: 평소에 게임·통화 앱이 HFP로 바꾸지 못합니다.
- 장점: 끄는 순간 강제로 A2DP로 돌아와서, "통화가 끝나도 안 돌아오는" Windows 문제가 같이 해결됩니다.
- 단점: 드라이버 재열거와 HFP 서비스 레벨 연결(RFCOMM)을 다시 맺어야 해서, 전환에 몇 초가 걸릴 것으로 예상합니다 (미측정).
- 단점: 마이크 장치가 시스템에서 사라졌다 생기므로, 실행 중인 통화 앱이 마이크를 다시 못 잡을 수 있습니다.
- 단점: 관리자 권한이 필요합니다.

### 무전기 방식과 비교

|  | 서비스 토글 | 무전기 방식 |
| --- | --- | --- |
| 전환 방법 | 핸즈프리 서비스 켜기/끄기 | 마이크 스트림 열기/닫기 |
| 예상 지연 | 수 초 | 0.5\~1.5초 |
| 누르는 단위 | 통화 시작·끝 | 말할 때마다 |
| 다른 앱의 HFP 전환 | 막음 | 못 막음 |
| 관리자 권한 | 필요 | 불필요 |

두 방식은 합칠 수 있습니다. 평소에는 핸즈프리를 꺼 두고, 통화 모드에 들어갈 때만 켜서 그 안에서 무전기 방식으로 쓰는 구조입니다.

## 기존 도구 현황

핸즈프리에 갇힌 걸 풀어 주는 도구(StereoKeeper)는 이미 있습니다. 비어 있는 건 Windows용 "누르면 말하기 + 프로필 자동 전환 + 가상 마이크" 도구입니다.

| 도구 | 플랫폼 | 하는 일 |
| --- | --- | --- |
| [StereoKeeper](https://github.com/Avazbek22/StereoKeeper/releases/latest) (구 BluetoothHandsFreeToggle) | Windows | 핸즈프리에 갇힌 헤드셋을 스테레오로 복구. 핸즈프리 서비스 재시작(소프트 리셋), 항상 스테레오 유지, 통화 모드 전환 알림. 트레이 앱, MIT |
| [win10-bluetooth-headphones](https://github.com/stanleyguevara/win10-bluetooth-headphones) | Windows | 핸즈프리(111E)·A2DP(110B) 서비스를 끄고 켜서 이어폰 연결 자체를 제어하는 스크립트 |
| [ToothTray](https://github.com/m2jean/ToothTray) | Windows | 블루투스 오디오 연결 트레이 앱. Core Audio API로 연결 |
| [bttray](https://github.com/andrew-d/bttray) | Linux | 트레이 아이콘으로 a2dp\_sink ↔ handsfree\_head\_unit 전환 |
| `pactl set-card-profile` 스크립트 ([예시](https://gist.github.com/crigertg/b0a745cc5d3f09ced0f65239bdd76d62)) | Linux | 단축키로 프로필 전환. 전환 후 3초 대기 |
| PulseAudio `module-bluetooth-policy` | Linux | 녹음 스트림이 생기면 자동 전환 |
| [BTMicFix](https://github.com/Endda/BTMicFix/) | Android | `setCommunicationDevice()`로 HFP 강제 전환 |

Windows에서는 오히려 통화가 끝나도 A2DP로 돌아오지 않는 문제가 많이 보고되고, 사용자들은 핸즈프리 드라이버를 끄는 식으로 대처합니다 ([예시](https://learn.microsoft.com/en-us/answers/a/6889841)).

## 현실적인 해결책

| 방법 | 비용 | 듣는 음질 | 내 목소리 음질 |
| --- | --- | --- | --- |
| 통화 마이크를 노트북 내장 마이크로 지정 | 없음 | A2DP 유지 | 내장 마이크 수준 |
| 유선 이어폰 | 저렴 | 유지 | 유지 |
| 무전기 방식 전환 도구 (직접 제작) | 개발 시간 | 말할 때만 저하 | HFP 수준 |
| USB 블루투스 동글 (Creative BT-W5 등) | 동글 구매 | 코덱 지원 시 개선 | aptX Voice 32kHz |
| LE Audio 지원 이어폰·PC | 기기 교체 | 유지 | 개선 |
| 핸즈프리 서비스 토글 (StereoKeeper 또는 직접 제작) | 없음 | 통화 모드 밖에서는 유지 | 통화 모드에서 HFP 수준 |

내 목소리 음질은 어느 방법이든 PC에서 AI 대역폭 확장(NVIDIA Broadcast 등)을 추가로 걸 수 있습니다.
