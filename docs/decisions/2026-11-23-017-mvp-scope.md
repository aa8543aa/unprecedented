# MVP 범위 확정

> **한 줄 이유:** 화면 디자인에 필요한 것만 MVP로 두고, 근거가 약하거나 없어도 동작하는 요소는 post-MVP로 미룬다.

- 회의록: [2026-11-23 화면 디자인과 MVP 범위](../meetings/2026-11-23-design-mvp.md)
- 상태: 채택

## 배경

[화면 디자인](2026-11-23-017-design-main-screen.md)이 정해져, 이를 바탕으로 MVP 기능을 나눈다. 이슈 #4의 완료 조건이다.

## 검토한 선택지

1. **화면에 보이는 것 전부를 MVP로**: 처음부터 완성도가 높다 / 경사도, 사고 확률처럼 근거가 약한 계산까지 들어가 늦어진다
2. **디자인의 핵심 흐름만 MVP로**: 빨리 동작하는 버전이 나온다 / 부가 요소는 나중에 붙인다

## 결정

선택지 2.

**MVP**

1. 프로젝트 구조와 부상도 계산 모듈 (화면과 분리, 브라우저 안 계산)
2. 주행 전 설정 화면 (몸무게, 자전거 종류, 헬멧, 카메라 선택, 기기에 저장)
3. 주행 화면 UI (상단 속력, 좌우 부상도 막대·%·전치·단계, 대상 선택, 고지 문구)
4. GPS 속력 측정 (GPS가 없을 때는 슬라이더로 입력)
5. 카메라 백미러 배경 (#18, post-MVP에서 MVP로 이동)

**post-MVP**

- 경사도 반영 (속도와 이중 계산되지 않게 설계)
- 사고 확률 표시
- 25km/h 기준선 표시
- 주행 기록 저장
- 정적 배포 (HTTPS 호스팅)
- 안드로이드 APK 포장 (Capacitor)

## 이유

- 디자인의 핵심은 "속도 → 나와 상대의 부상도"이고, 나머지는 없어도 이 흐름이 동작한다.
- 경사도와 사고 확률은 근거 데이터가 약하다.

## 영향

- MVP 각 항목은 이슈 1개, PR 1개로 진행한다.
- 실기기 확인(GPS, 카메라)에는 HTTPS 주소가 필요하다. 정적 배포가 post-MVP이므로, MVP 단계에서는 개발 서버와 브라우저 슬라이더로 확인한다.
