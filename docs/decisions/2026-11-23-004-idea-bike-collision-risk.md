## 배경

프로젝트 주제는 "전례없는"이다. 후보마다 비슷한 서비스를 먼저 검색하고, 선례가 있으면 탈락시키는 기준으로 골랐다. 탐색한 후보와 검색 결과는 이슈 #4 코멘트에 있다.

## 검토한 선택지

1. **소리 블랙박스** (앱별 시스템 소리를 30초씩 기록해 "방금 그 소리" 찾기): 선례 없음 / 네이티브 데스크톱 앱, 앱별 오디오 캡처가 까다로움
2. **만능 전송 취소** (메신저 전송을 5초 붙잡아 취소 가능): 선례 없음 / 패킷 홀드와 관리자 권한 필요, 메신저 반응이 검증되지 않음
3. **무거워지는 손** (딴 짓을 하면 마우스·키보드가 점점 느려짐): 원안(딴 짓 경고)은 선례가 많고 입력 저하만 빈자리 / 네이티브 앱, 저수준 훅 필요
4. **자전거 충돌 위험 계산기**: 선례 없음, 웹앱으로 가능 / 데이터가 자동차 충돌 속도 기준이라 정밀도에 한계

## 결정

**자전거 충돌 위험 계산기**(이름 미정)로 확정한다. 자전거를 타는 동안 GPS 속도를 읽어 "지금 무언가와 부딪히면" 나와 상대가 입을 피해를 보여준다.

MVP에 넣을 것:

- 속도 입력: GPS 실시간 속도, 또는 슬라이더로 직접 입력
- 충돌 대상 선택: 보행자 / 자전거 / 오토바이 / 승용차 / 트럭 (상대 속도는 기본값 또는 직접 입력)
- 화면 왼쪽은 나, 오른쪽은 상대. 서로의 사망률과 부상 정도를 막대 또는 원형 % 그래프로 나란히 표시
- 두 가지 표시를 함께 둔다
  - **계산 모드:** "이 속도로 OO와 부딪히면"이라는 전제를 명시한 사망률·부상 정도
  - **경각심 게이지:** 속도가 오를수록 빨개지는 위험 체감 지표
- 사고 확률은 대략치로만 쓰고 "참고용 추정"이라고 표시한다

계산 모델 (과제 수준):

- 각자 받는 충격: Δv = 상대 질량 / (내 질량 + 상대 질량) × 접근 속도 ([지표 리뷰](https://arxiv.org/pdf/2108.02403))
- 사망 확률은 Δv의 4제곱에 비례하는 모델을 쓰고, 보행자 실측치(32km/h 5%, 48km/h 45%, 64km/h 85%, [EU 자료](https://road-safety.transport.ec.europa.eu/statistics-and-analysis/statistics-and-analysis-archive/pedestrians/no-speed-no-mass-and-no-protection_en))로 크기를 맞춘다
- 보호 정도는 도로 이용자별 "중상 위험 10%" 접근 속도로 반영한다: 보행자 29, 자전거 44, 오토바이 48, 승용차 운전자 112km/h ([Lubbe 2022](https://doaj.org/article/4a301cd181334d83ab6becfaff54f158))

## 이유

- 속도별 실시간 사망·사고율을 보여주는 앱, 나와 상대의 피해를 나란히 비교하는 계산기 모두 검색에서 찾지 못했다. 비슷한 것은 경로 위험 앱([SafePath](https://www.bikeradar.com/news/new-safepath-app-alerts-cyclists-to-route-hazards))과 훈련 부하 부상 위험 앱([OnTracx](https://apps.apple.com/ca/app/ontracx/id6473828071))으로 개념이 다르다.
- 다른 생존 후보는 모두 네이티브 데스크톱 앱이 필요하고 기술 위험이 크다. 이 후보는 브라우저만으로 된다.
- 근거 데이터가 공개되어 있어 숫자의 출처를 밝힐 수 있다.

## 영향

- 숫자는 의료·법적 근거가 아니다. 화면에 전제와 "참고용 추정"을 반드시 표시한다.
- 데이터 대부분이 자동차와의 충돌 기준이다. 혼자 넘어지는 사고는 다루지 않는다.
- 경사 같은 요인은 대부분 속도를 통해 작용하므로, 추가하면 이중 계산이 된다. 추가하려면 post-MVP에서 다시 검토한다.
- 이슈 #4의 완료 조건에 따라 MVP 기능을 각각 이슈로 나눠야 한다. 이는 디자인을 정한 뒤 진행한다.
