# 앱 형태와 연산 위치: React 웹앱 + 브라우저 안 계산

## 배경

처음 스택(React + Vite + TypeScript)은 아이디어가 정해지지 않은 상태에서 고른 것이라, 아이디어가 정해지면 다시 보기로 했다. 아이디어가 [자전거 충돌 위험 계산기](2026-11-23-004-idea-bike-collision-risk.md)로 정해졌다.

## 검토한 선택지

1. **React 웹앱 유지 + 정적 배포, 필요하면 Capacitor로 APK**: 코드 하나로 웹과 안드로이드를 모두 낼 수 있다 / 브라우저에서는 화면이 켜져 있을 때만 GPS가 안정적이다
2. **처음부터 네이티브(Kotlin) 또는 React Native**: 백그라운드 GPS가 자유롭다 / 스택을 바꿔야 하고, 웹으로 공유할 수 없다
3. **계산 서버를 따로 둠**: 나중에 모델을 바꾸기 쉽다 / 지금은 계산이 가벼워 서버가 필요 없고, 운영 비용과 지연이 생긴다

## 결정

- 스택은 **React + Vite + TypeScript를 유지**한다.
- `npm run build`로 만든 정적 파일을 HTTPS 호스팅(예: GitHub Pages)에 올린다. 브라우저 위치 권한은 HTTPS에서만 동작한다.
- 안드로이드 앱이 필요해지면 **Capacitor**로 같은 코드를 감싸 APK를 만든다 (post-MVP).
- **별도의 실시간 연산 서버를 두지 않는다.** 위험도 계산은 브라우저 안에서 한다.
- 대신 계산 부분은 화면과 분리된 모듈로 만든다. 화면은 "속도와 대상을 넣으면 결과를 돌려주는" 인터페이스만 알게 해서, 나중에 서버로 옮길 때 그 인터페이스의 구현만 바꾸면 되게 한다.

## 이유

- 계산은 공식 몇 개라 서버 없이 즉시 된다. 오프라인에서도 동작한다.
- 위치 데이터가 기기를 떠나지 않아 개인정보 부담이 없다.
- 계산을 인터페이스 뒤로 분리하면, 나중에 모델을 키우거나 데이터를 모으고 싶어졌을 때 서버로 옮기는 비용이 작다.

## 영향

- 브라우저 웹앱은 백그라운드 GPS가 안 된다. 주행 중에는 화면을 켜 두어야 한다. 백그라운드가 필요해지면 Capacitor 위치 플러그인을 검토한다.
- iOS 앱으로 만들려면 Mac이 필요하다.
- 프로젝트 구조와 기능 정의는 디자인을 먼저 정한 뒤, 그 디자인을 참고해 설계한다.
