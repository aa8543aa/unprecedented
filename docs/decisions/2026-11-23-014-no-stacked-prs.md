# PR은 항상 main 기준, 스택 PR 금지

> **한 줄 이유:** 스택 PR은 머지 순서와 저장소 설정에 따라 결과가 달라져, 실제로 main 누락 사고가 났다.

- 이슈: #14
- PR: (이 PR)
- 회의록: [2026-11-23 스택 PR 머지 누락 대응](../meetings/2026-11-23-merge-recovery.md)
- 상태: 채택 ([002](2026-11-23-002-workflow-issue-pr.md)를 보완)

## 배경

초기 세팅 PR 6개를 스택으로 올렸는데, head 브랜치 자동 삭제가 꺼져 있어 base가 main으로 바뀌지 않았다. 그 결과 #5 외에는 main에 반영되지 않았다.

## 검토한 선택지

1. **스택 유지 + 머지 순서 주의**: 병렬로 작업하기 편하다. 사람이 실수하기 쉽고, 설정에 의존한다.
2. **항상 main 기준 PR**: 앞 작업이 머지될 때까지 기다리거나 rebase해야 한다. 결과는 늘 예측 가능하다.

## 결정

- PR의 base는 **항상 `main`** 으로 한다. 앞 PR에 의존하는 작업은 앞 PR이 머지된 뒤 main에서 브랜치를 새로 만든다.
- 머지 방식은 **Squash merge**를 기본으로 하고, 머지 후 head 브랜치를 삭제한다.
- 저장소 설정 `Automatically delete head branches`는 **켜지 않는다** (오너 결정). 브랜치는 머지할 때 PR 화면의 "Delete branch"로 직접 삭제한다.
- 이번 누락분은 예외로 PR 1개(#14)에 모아 main에 반영한다. 내용은 이미 각 PR(#6, #7, #9, #11, #13)에서 리뷰되었다.

## 이유

혼자 작업할 때는 병렬 작업의 이점이 작고, 협업으로 바뀌면 스택 PR의 실수 비용이 더 커진다.

## 영향

- CONTRIBUTING 2절에 "base는 항상 main"을 명시한다.
- 자동 삭제가 꺼져 있으므로 스택 PR은 다시 같은 문제를 일으킨다. 스택 금지 규칙이 유일한 안전장치다.
